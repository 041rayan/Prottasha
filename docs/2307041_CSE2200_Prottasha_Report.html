1. Introduction & Behavioral Framework

1.1 Problem Concept & Dopamine Traps

University students and young adults in Bangladesh are increasingly ensnared by pervasive digital dopamine loops. Short-form algorithmic media (TikTok, YouTube Shorts, Instagram Reels), predatory mobile gaming mechanics, online gambling platforms, and compulsive consumption of adult content (PMO) exploit the human brain’s mesolimbic dopamine pathway. By delivering intermittent, unpredictable bursts of novelty, these platforms engineer habitual, mindless opening loops that bypass conscious executive control.

Standard digital wellbeing tools and mobile timers fail systematically because they rely exclusively on conscious willpower and punitive restriction. Modern behavioral psychology demonstrates that willpower is an easily depleted cognitive resource. When a stressed, fatigued student attempts to resist a compulsive urge, sheer restraint almost universally collapses. Furthermore, conventional blockers display aggressive, shame-inducing failure screens that trigger guilt and cognitive dissonance. Guilt elevates cortisol and emotional stress, driving the user directly back into the very avoidance coping mechanisms (scrolling, gaming, or PMO) they sought to escape.

Prottasha (meaning “Hope” in Bengali) is a native Android application engineered to dismantle digital dopamine addiction through identity-first transformation and mindful friction rather than raw willpower. Built from the ground up to operate offline-first with zero-knowledge cryptographic privacy, Prottasha treats addiction recovery not as a binary battle of resistance, but as an ongoing process of accumulating behavioral evidence for an intentional self-image.

The app enforces six core behavioral protocols across its domain layer: 1. Identity-First Two-Step (AH-01, PC-01): The user first decides the type of person they aspire to become (e.g., “A focused software engineer who values presence with family”). Every recorded habit completion is mathematically logged as an immutable “vote” casting evidence for that identity. 2. Environmental Friction with Explicit Exit (EX-01, AH-07): Rather than blocking apps with frustrating error messages, Prottasha introduces a 15-second breathing countdown delay when a guarded application (e.g., YouTube or Instagram) is launched. An prominent, effortless button labeled “Step back to my ideal self” allows the user to exit cleanly back to the home screen. Clinical trials demonstrate that a simple 10–15s delay combined with an effortless exit achieves a ~57% drop in compulsive app openings. 3. Grayscale Friction (EX-02): By stripping colorful dopamine-triggering badges and thumbnails through Android accessibility display toggles, screen consumption drops by an average of 20 to 50 minutes per day. 4. Relapse Without Shame / Never Miss Twice (AX-6, AH-18, PC-18): When an avoid-habit lapse occurs, the app strictly forbids derogatory language or resetting streaks to zero. Instead, it prompts a three-stage reflection: What was the objective cue? How did I interpret it? What friction can I place next time? 5. Two-Minute Entry Scaling (AH-11): Daily habit targets are bounded to tiny initial increments (e.g., read 1 page, drink 250ml water) so that behavioral momentum is established before cognitive friction can reject the habit. 6. Mental Rehearsal & Urge Surfing (PC-06, EX-11): Guided visualization protocols de-sensitize cravings before they peak, utilizing a 10-second expanding/contracting circle rendered with Android ValueAnimator (4s inhale, 2s hold, 4s exhale).

1.4 Data Provenance, Privacy & Safety

Because Prottasha is designed to address stigmatized, deeply personal struggles (such as pornography addiction, compulsive gambling, and severe academic burnout), privacy is an inviolable architectural constraint rather than an optional setting.

  1. Zero Node Scraping Commitment: The ProttashaAccessibilityService registers strictly for window state changes (TYPE_WINDOW_STATE_CHANGED) to identify the foreground package name and normalize browser URL hostnames. The service never traverses the accessibility node tree, never reads on-screen text, never inspects form fields, never captures keystrokes, and never records passwords or private messages.
  2. Opaque UID Namespacing: To prevent forensic correlation between user accounts, database files, and cloud storage, user UIDs are never stored as plaintext file or database identifiers. The local database file name is generated via a SHA-256 hash of the UID: \[\text{DatabaseName} = \text{"prottasha\_"} + \text{SHA-256}(\text{FirebaseUID}) + \text{".db"}\]
  3. Client-Side Hardware-Backed Encryption: User habit records, daily usage logs, and private journal entries are encrypted at rest using SQLCipher 4.11.0 with AES-256 encryption. The passphrase is randomly generated, sealed by the Android Keystore, and stored in encrypted private preferences. If a device is rooted or physically inspected, the database remains unreadable.
  4. Local Encrypted Media: Unlike standard social apps that upload personal photos to unencrypted AWS/GCS buckets, user reflection images are stripped of all EXIF metadata, scaled to bounded dimensions, and stored in private app storage encrypted via AES-256-GCM.
  5. Verified Bangladesh Emergency Directory: Mental health crises require immediate, reliable intervention. Prottasha bundles and verifies primary Bangladesh emergency lifelines:
    • National Emergency Service: 999 (Police, Ambulance, Fire)
    • Kaan Pete Roi: +880 9612 119911 (First emotional support and suicide prevention helpline in Bangladesh)
    • Talk Hope Bangladesh: +880 9638 881 888 (Mental wellbeing and crisis counseling)
    • Women and Children Helpline: 109 (Government protection helpline)
    • National Health Helpline: 16263 (Ministry of Health and Family Welfare)

3. Architecture, Navigation & Cryptographic Data Design

3.1 End-to-End Architecture & Data Flow

Prottasha is architected according to Clean Architecture and the Model-View-ViewModel (MVVM) pattern. The system is decomposed into four discrete, decoupled layers with unidirectional dependency flow: 1. Presentation / UI Layer: Activities, Fragments, ViewHolders, and Custom Views. The UI observes observable state streams (LiveData) emitted by ViewModels and binds views through auto-generated View Binding classes. 2. Domain & Engine Layer: Pure-Java business logic, state machines, and mathematical calculators. This layer contains no Android SDK imports, making it 100% unit-testable on the local JVM. 3. Data / Repository Layer: Unified gateways coordinating between local encrypted SQLite storage and cloud backends. Handles session lifecycle switching, offline caching, and serialization. 4. Platform & Storage Layer: Low-level Android subsystems including SQLCipher Room, Android Keystore, UsageStatsManager, AccessibilityService, AlarmManager, and Firebase SDKs.

4.2 Habit Ledger & Consistency Engine

Unlike simplistic habit trackers that increment a single mutable counter, Prottasha maintains an immutable, append-only event ledger. Every user interaction generates a HabitEventEntity bearing a unique cryptographically random nonce. If duplicate events are received due to rapid double-tapping or synchronization replays, the unique index rejects the duplicate transaction.

4.2.1 DayBoundary & Timezone Offset Logic

University students and night owls frequently stay awake past midnight. Traditional trackers that roll over the calendar date at 12:00:00 AM break user streaks prematurely. Prottasha introduces a configurable DayBoundary primitive: \[\text{DayBoundaryOffset} = \text{04:00 AM (Default)}\]

The effective epoch day for any timestamp \(T\) in milliseconds is computed as: \[\text{EffectiveTimestamp} = T - (\text{CutoffHour} \times 3,600,000)\] \[\text{EpochDay} = \lfloor \frac{\text{EffectiveTimestamp} + \text{TimezoneOffset}(\text{EffectiveTimestamp})}{86,400,000} \rfloor\]

This guarantees that activities completed at 02:30 AM are truthfully attributed to the psychological “day” that began the previous morning, maintaining flawless consistency across Bangladesh Standard Time (BST, UTC+6).

4.2.2 Mathematical Streak and Consistency Formulations

Prottasha evaluates three distinct habit modalities with mathematical rigor: 1. Build Habits (Positive Accumulation): \[\text{DailyStatus}(d) = \begin{cases} \text{COMPLETED}, & \text{if } \sum \Delta \text{Value}(d) \ge \text{TargetValue} \\ \text{INCOMPLETE}, & \text{otherwise} \end{cases}\] \[\text{CurrentStreak} = \text{Consecutive unbroken sequence of COMPLETED days counting backward from } d_{\text{today}} \text{ or } d_{\text{yesterday}}\] 2. Avoid Habits (Harm Reduction & Rebound Recovery): Traditional trackers reset avoid streaks to zero upon a single lapse. Prottasha implements the “Never Miss Twice” protocol (AH-18): \[\text{AvoidStatus}(d) = \begin{cases} \text{SUCCESS}, & \text{if Lapses}(d) = 0 \\ \text{REBOUND}, & \text{if Lapses}(d) = 1 \text{ AND } \text{Lapses}(d+1) = 0 \\ \text{BROKEN}, & \text{if Lapses}(d) \ge 1 \text{ AND } \text{Lapses}(d+1) \ge 1 \end{cases}\] A single lapse does not destroy the streak; instead, it enters a “Rebound Horizon” state. If the user successfully avoids the behavior the subsequent day, the streak is preserved with a rebound flag, eliminating the catastrophic “what-the-hell” relapse spiral. 3. Amount Habits (Fractional Target Completion): \[\text{CompletionRatio}(d) = \min \left(1.0, \frac{\sum \Delta \text{Value}(d)}{\text{TargetValue}}\right)\]

6.3 Accessibility Service & Non-Intrusive Observation

Android’s AccessibilityService is frequently abused by malicious applications for keylogging and UI scraping. Prottasha adheres to strict ethical and Google Play privacy standards.

In res/xml/accessibility_service_config.xml, the service declares:

<accessibility-service xmlns:android="http://schemas.android.com/apk/res/android"
    android:accessibilityEventTypes="typeWindowStateChanged"
    android:accessibilityFeedbackType="feedbackGeneric"
    android:accessibilityFlags="flagDefault"
    android:canRetrieveWindowContent="false"
    android:notificationTimeout="100" />

By setting android:canRetrieveWindowContent="false", the Android OS cryptographically prevents the service from inspecting on-screen text, form inputs, passwords, or personal messages. The service only reads the package name from the top-level window event to determine if an active Guard rule applies.

6.4 Foreground Service & Notification Management

To support deep focus sessions without being terminated by Android’s Doze mode or Low Memory Killer (LMK), Prottasha implements ProttashaFocusService. Declared with android:foregroundServiceType="specialUse", the service adheres to modern Android 14/15 restrictions.

The service manages the notification lifecycle: - Notification Channel: channel_focus configured with IMPORTANCE_LOW to prevent annoying audio chimes while maintaining high visibility. - Action Buttons: The notification provides two direct action buttons: Pause/Resume and Finish. These dispatch explicit Intents to the service without opening the full UI. - Non-Sticky Termination: When the timer expires or the user taps Stop, the service calls stopForeground(STOP_FOREGROUND_REMOVE) and stopSelf(), guaranteeing that no orphan background processes linger in memory.

6.5 Broadcast Receivers & AppWidget Architecture

Prottasha implements four specialized BroadcastReceiver components: 1. ReminderAlarmReceiver: Invoked by Android AlarmManager using setExactAndAllowWhileIdle(). It builds and posts a high-priority notification at the user’s scheduled habit reminder time. 2. ReminderRescheduleReceiver: Registered in the Android Manifest to listen for BOOT_COMPLETED, MY_PACKAGE_REPLACED, TIME_SET, and TIMEZONE_CHANGED. When any of these system broadcasts fire, the receiver schedules a background worker to recalculate all pending exact alarms against the updated clock, preventing missed reminders. 3. BatteryOrAirplaneReceiver: Reacts dynamically to BATTERY_LOW and AIRPLANE_MODE events. When battery drops below 15%, the app disables optional animated canvas sweeps to conserve battery. 4. TodayWidgetProvider: Connects Prottasha’s local Room database to the Android home screen using RemoteViews. When an event is recorded in MainActivity, an explicit update broadcast refreshes the widget instantly.

6.6 External REST API & Network Engine

Prottasha integrates background HTTP networking via OkHttp 4.12.0 to maintain an up-to-date directory of verified mental health crisis services in Bangladesh.

The network architecture operates as follows: 1. Remote Endpoint Request: An asynchronous worker issues an HTTPS GET request to https://prottasha.org/api/support/bangladesh.json. 2. Integrity Verification: The received payload is verified against a pre-shared SHA-256 integrity checksum. If the payload is truncated or corrupted, the parser rejects the update. 3. JSON Deserialization: The verified JSON string is deserialized into DirectoryEntryEntity models and upserted into the Room database. 4. Bundled Offline Asset Fallback: If the user is offline or the network call fails, the repository seamlessly falls back to assets/support_directory_fallback.json, guaranteeing that the user is never left without emergency telephone numbers during a crisis.

7.3 Academic Limitations & Boundaries

In the spirit of scientific transparency, Prottasha operates within explicit design boundaries: 1. Firebase Spark Tier Constraints: The application operates strictly within the free Firebase Spark tier. Because Cloud Functions are unavailable on the free tier, cascading data deletion (pod messages, reactions, reports) is coordinated via client-side paginated batches enforced by strict Firestore Security Rules prior to Firebase Auth account deletion. 2. Pure Java 17 Rationale: The project is written 100% in Java 17 using standard Android Views and View Binding. Modern declarative frameworks like Jetpack Compose were deliberately omitted to maintain predictable memory usage on low-end hardware and demonstrate mastery of core Android fundamentals. 3. Anti-Surveillance Privacy Boundaries: Prottasha queries only launcher applications (Intent.CATEGORY_LAUNCHER), avoiding the intrusive QUERY_ALL_PACKAGES permission. The Accessibility Service strictly inspects window change metadata without scraping screen text. 4. Honest Metrics Guarantee: Prottasha never generates fake “hours saved” numbers or artificial streak claims. If usage data is absent, the UI presents an honest empty state.
